# NodeSeek 自动签到

作者与维护：[liuzhihang](https://github.com/liuzhihang)。这是独立编写的单账号 Loon 插件，仅支持 `https://www.nodeseek.com`，不包含 DeepFlood、多账号、账号密码登录或验证码服务。

## 安装与首次启用

`v1.1.0` 存在手动运行捕获或签到确认条目时缺少请求上下文、误入签到分支的问题。`v1.2.0` 改为显式入口并默认拒绝；升级前不要手动运行旧捕获、确认条目。必须同时更新远程 `.lpx` 与 JS，混用旧配置时新版脚本会停止，不回退到签到。

安装入口为 `plugins/nodeseek.lpx`，插件统一引用本仓库 `main` 上的远程 JS。首次使用前需确认 `.lpx` 和 JS 均已发布到 `main`；仅本地提交不会更新下载地址。本实现已完成离线模拟测试，尚未经过真实 Loon 或账号签到验收。

1. 在 Loon 3.5.1（983）或更高版本中从 URL 添加插件：

   ```text
   https://raw.githubusercontent.com/liuzhihang/loon-plugin/main/plugins/nodeseek.lpx
   ```

2. 按自己的设备设置启用插件、脚本和 MitM，安装并信任 Loon 的 MitM 证书，保持 Loon 接管所用浏览器的流量。在插件参数中，“捕获登录会话”默认开启，“自动签到”默认关闭。
3. 在受该设备 Loon 接管的浏览器登录 NodeSeek，再进入或刷新 [签到页 `/board`](https://www.nodeseek.com/board)，**不需要点击签到按钮，也不要手动运行捕获入口**。页面响应为 HTTP 200、有效 HTML，且初始数据中存在有效的已登录用户时，才保存请求中的 Cookie 和 User-Agent。首次成功提示“登录会话已保存”，更换会话提示“登录会话已更新”，相同会话提示“登录会话已存在”。捕获不发送网络请求、不修改网页响应，也不新增“今日已签到”记录；其他页面和未登录页面不会保存。
4. 在该插件的参数页面开启“自动签到”，并设置奖励模式与执行时间。默认计划为每天设备本地时间 **09:30**；需要先开启自动签到才会按此计划执行。保存会话后可关闭“捕获登录会话”，需要更新会话时再开启。

同日若有可信日期的确认记录，运行签到任务会显示“本地记录：今日已有确认结果”，并注明“本次未请求服务器”；这不能用来验收自动签到接口。没有当日记录则向服务端提交一次 POST。只有实际出现“签到成功”或“服务端：今日已签到”，才分别表示服务端确认了新签到或重复签到。自动签到开关关闭时，定时及手动执行签到入口均会停止，不发送请求。

## 两个入口的分工

| 入口 | 触发与用途 | 手动运行时 |
| --- | --- | --- |
| `NodeSeek会话捕获_自动触发`（RESPONSE） | 进入或刷新已登录的 `/board` 后自动保存会话，不发签到请求 | 没有网页响应时只提示刷新签到页，不读本地会话、不签到 |
| `NodeSeek执行签到_会发请求`（CRON） | 自动签到开启、参数完整时，按计划执行；最多一个 POST | 仍须自动签到开启及参数完整；缺失参数即停止 |

旧版第三条 `NodeSeek签到确认` 用于观察用户手动签到响应，`v1.2.0` 不再添加这条可选规则。捕获与执行仍共用同一个远程 JS，但用途通过明确参数区分。仅手动运行一个名字含“抓包”的条目，不代表存在真实网页响应。

首次启用后的真实运行由使用者自行核实。遇到登录过期，重新登录并刷新 `/board` 更新会话；遇到访问拒绝、安全验证或限流，先暂停定时任务，在官网核实，不连续运行。

## 主配置接入

如果通过主配置管理插件，在现有 `[Plugin]` 中保留一个远程插件入口即可：

```ini
[Plugin]
https://raw.githubusercontent.com/liuzhihang/loon-plugin/main/plugins/nodeseek.lpx,tag=NodeSeek,enabled=true
```

捕获规则、定时任务和 `www.nodeseek.com` 的 MitM 主机声明均由 `.lpx` 插件管理；JS 由 Loon 从插件中的远程地址加载。主配置只需引用插件，执行时间和开关在插件参数中调整。

迁移曾手动加入的 NodeSeek `[Script]` 条目时，应移除对应的本地捕获和定时条目，保留一份插件入口，避免重复运行。原有 `NodeSeek_Session` 键可继续使用，不需要复制或导出 Cookie。停用“捕获登录会话”只停止保存动作；停用整个插件才撤销由该插件引入的 MitM 声明，其他插件的解密范围保持各自设置。

## 参数与结果

插件参数使用 Loon 新版 `[Argument]` 语法。捕获开关、自动签到开关和时间由 Loon 管理，奖励模式和同日跳过通过 `$argument` 传给脚本：

下表是插件界面的默认设置。签到入口必须传入完整的 `autoCheckin`、`random`、`useCache` 布尔参数；未传参数、参数不完整、名称不匹配或绑定到网页响应上下文时，脚本在读取本地会话前停止，不猜测奖励模式。请保留这两个入口名称并同时更新插件和 JS。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 捕获登录会话 `capture` | 开启（`true`） | 进入或刷新已登录的 `/board` 即可保存会话，无需先签到；保存成功后可关闭 |
| 自动签到 `autoCheckin` | 关闭（`false`） | 保存会话后由使用者开启，控制定时任务，也作为手动执行签到入口的开关 |
| 执行时间 `cronExpression` | `30 9 * * *` | 设备本地时间，每天 09:30；可在插件参数中调整 |
| 随机奖励 `random` | 关闭（`false`） | 关闭发送 `random=false`，开启发送 `random=true`。该值是奖励模式，不是随机字符串或防缓存参数 |
| 同日跳过 `useCache` | 开启（`true`） | 同一会话已有当日确认记录时跳过网络请求。关闭后每次运行均提交一次 POST，仍不自动重试 |

公开的 NodeSeek Pro v1.0.8 把 `random=false` 标注为固定 5 个鸡腿，`true` 标注为随机奖励。这是源码研究结果，不保证当前网站或账号的实际奖励；脚本只显示服务端返回且通过类型校验的 `gain`、`current` 数字，不自行补上“5”。

| 执行结果 | 本地记录 | 含义 |
| --- | --- | --- |
| 签到成功 | `kind: success` | HTTP 200、有效 JSON、`success === true`，且没有挑战、登录失效或访问拒绝等信号 |
| 服务端：今日已签到 | `kind: duplicate` | HTTP 200、布尔 `success` 和完整的“已完成签到”肯定句，可带“明天再来”等已支持后缀；含未知补充说明时停止，不计为新签到或新奖励 |
| 本地记录：今日已有确认结果 | 不更新 | 本次未请求服务器，只复用了同一会话的当日确认记录 |
| 签到未完成 | 不更新 | 网络错误、异常 HTTP 状态、非 JSON、未知响应或未明确成功；不把本次运行写成成功 |

本地日界固定使用 **UTC+8**，不依赖设备时区；定时任务时间使用设备本地时区。站点实际日界尚未实测，本地记录只是减少重复请求的策略。如需由服务端确认，先自行核实网站状态，再关闭“同日跳过”手动运行一次。该记录不是跨脚本实例的互斥锁，请只配置一份定时任务。

页面捕获不根据页面上的“已签到”文案建立记录；同一 Cookie 与 User-Agent 已有的非未来确认记录可保留，切换会话时不继承旧记录。执行签到的 POST 使用请求开始时的日期，跨午夜返回时不会把结果直接记入次日，也不会覆盖同一会话较新的确认记录。旧版有效的确认记录可沿用，无需为升级清空会话。

## 接口与停止条件

- 单次 `POST https://www.nodeseek.com/api/attendance?random=false` 或 `random=true`，请求体为 JSON `{}`，复用已保存的 Cookie 和浏览器 User-Agent，发送同站 Origin 与 Referer。
- 页面捕获仅匹配 `GET https://www.nodeseek.com/board`，兼容末尾斜杠及查询参数。只解析 `temp-script` 内的 Base64 JSON，检查 `user.member_id` 为有效正整数；不执行页面代码、不保存用户资料。页面数据格式变化时停止保存并保留旧会话。正常页面引用 Cloudflare 检测脚本本身不判为挑战；挑战标头、验证页标题和交互验证信号仍会停止捕获。
- 只接收 HTTP 200 的 JSON 对象；`"true"`、`1`、仅有奖励文案或未知字段都不当作 `success === true`。重复签到采用独立判断，不能凭文案中出现“鸡腿”就当作成功。
- HTTP 401、JSON `status: 404`（公开签到脚本的失效判据）或明确未登录提示要求重新登录；HTTP 404 按接口异常处理。HTTP 403、429、安全挑战和自动化拒绝会提示暂停核实。Cloudflare 挑战（包括 HTTP 200 挑战页）不会尝试解决。
- 请求超时为 15000 毫秒，脚本总超时为 30 秒。不自动重试任何签到请求，不跟随任何重定向，不关闭 TLS 证书校验，不使用自动 Cookie 容器。超时可能发生在服务器处理后，因此只报告结果不确定，需在官网核实。
- 确认成功后如本地记录写入失败，保留服务端成功结果，同时提示记录未保存。请求期间若保存了另一份会话，不用旧请求覆盖新会话。
- 每次有效页面捕获，包括首次、更新及相同会话，都会调用一次通知接口。日志会注明接口已调用，不能据此保证系统显示横幅；显示仍取决于系统通知权限和 Loon 通知设置。通知异常不改变已保存的会话或已确认的服务端结果，只记录预设失败提示，不输出异常原文。

## 本地数据与排查

仅使用 Loon 本地存储键 `NodeSeek_Session`，内容为最近一次验证过的 Cookie、User-Agent 与可选的 `{ day, kind }` 日期记录。单账号运行，下一次成功捕获会替换旧会话；Cookie 不重复写入其他键，不保存密码、完整响应、账号资料或额外请求头。

日志和通知只使用预设的错误分类与校验过的奖励数字，不输出 Cookie、User-Agent、响应正文、服务端原始消息或网络异常文本。存储的会话属于敏感数据，请勿把本地存储或抓包请求头加入仓库或反馈截图。清除会话时只删除 `NodeSeek_Session`；无需清空其他插件数据。

没有捕获通知时，先确认远程插件及 JS 都已更新至 `v1.2.0`，插件与“捕获登录会话”均已开启，再在已登录的浏览器刷新 `/board`，不要仅切回已经打开的标签页。规则需要实际的 HTTP 200 页面响应；缓存未重新请求或仅返回 304 时不会保存。在 `NodeSeek会话捕获_自动触发` 日志区分“已保存 / 已更新 / 已存在”和通知调用状态。日志已调用通知接口但没有横幅时，检查 Loon 的通知设置和系统通知权限；这不能解释为会话未保存。登录页、错误页、挑战页、缺少 User-Agent 或存储失败都会保留原会话。

Mac Chrome 也可用于捕获，前提是该浏览器流量实际经过 Mac 上的 Loon，并已有有效的脚本、MitM 和证书信任设置。手机镜像中的浏览器仍在手机运行，应在实际运行任务的同一设备完成捕获；不能仅凭配置文件同步推断会话也已同步。需要排查时只查看脚本的预设状态日志，不导出 Cookie 或完整网络请求。

没有按计划执行时，检查插件参数“自动签到”是否开启，以及“执行时间”是否为有效 Cron 表达式。当前代码版本为 `v1.2.0`；同时更新插件及 JS 后应只有上述两个条目。看到旧的三条或缺参提示时，先检查资源更新，不反复运行旧捕获条目。
